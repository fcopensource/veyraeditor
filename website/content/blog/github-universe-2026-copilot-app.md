GitHub Universe 2026 took place on **October 28** in San Francisco, and its message was simple: *"Completed work, not more code, is the output that matters."* Nearly every announcement was about getting Copilot from an issue all the way to a merged pull request. A few weeks on, these features are showing up in VS Code and JetBrains IDEs too, so here's the recap.

## The GitHub Copilot app

The headline was a new **GitHub Copilot app**, pitched as *"From issue to merge, in one app."* It's a home for agent work outside the editor: you hand Copilot an issue, watch the sessions run, review and merge. Sessions carry over between the app, VS Code, the CLI and the web, so you can start in one place and finish in another.

## Copilot Fusion: several models, one task

**Copilot Fusion** splits a task across models and picks which one handles each part. GitHub's numbers, from the Artificial Analysis Coding Agent Index: *"Fusion Max scored within two points of Opus 5.5 Max at half the cost and 40% less time per task."* VS Code 1.146 has since added Fusion to its model comparison view.

## Projects: agents across many repositories

**Copilot Projects** run agent work across several repositories at once, in parallel sessions. GitHub says they're *"available natively in the GitHub Copilot app starting today."* For teams with a frontend, backend and shared library in separate repos, that's the first time one Copilot task can span all three.

## Code Review Max, automations and Enterprise access

- **Copilot code review Max** is a deeper review tier aimed at high-severity bugs.
- **Copilot automations** can now propose improvements based on their own results.
- **GitHub Enterprise customers** can use Copilot features without a separate Copilot subscription, through GitHub Sales today, with self-serve "coming soon".

GitHub also said it added 4 million CPU cores, 160 PB of fast storage and 50 Tb/s of network capacity this year to keep up with agent traffic.

## What it means for you

Copilot is moving from autocomplete to a system that runs whole tasks. Whether you use it or not, you still review the diffs that come out, and that's where good tooling helps.
